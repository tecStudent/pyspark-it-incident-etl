# v1.1.0 — Local Airflow Orchestration and CI Hardening

## Destaques

- Orquestração local do pipeline incremental com Apache Airflow 3.3.1.
- DAG separada em landing, Bronze, Silver, Gold, reconciliação e resumo.
- Ambiente reproduzível com LocalExecutor, PostgreSQL, Java 17 e PySpark 4.1.2.
- Publicação automatizada da imagem executável no GitHub Container Registry.
- CodeQL, Dependency Review, Dependabot, Trivy, `CODEOWNERS` e política de segurança.
- Docker Actions atualizadas para versões compatíveis com Node.js 24.

## Resultados de referência

- 278 testes automatizados aprovados no ambiente Docker.
- Quality gate de cobertura mantido acima do mínimo de 50%.
- Manifesto do dashboard `HEALTHY`, com cinco de cinco contratos válidos.
- Pipeline incremental, reconciliação e controles de governança validados.

## Qualidade da release

A release é validada pelo conjunto completo de testes e pelo release readiness:

~~~bash
docker compose run --rm spark python3 -m pytest -q

docker compose run --rm spark \
  python3 src/release_readiness.py --check --version 1.1.0
~~~

A publicação permanece condicionada à aprovação dos checks da `main`.

## Executar localmente

Para executar os testes do pipeline:

~~~bash
docker compose build
docker compose run --rm spark python3 -m pytest -q
~~~

Para iniciar o ambiente Airflow:

~~~bash
cp .env.airflow.example .env.airflow

docker compose --env-file .env.airflow \
  -f docker-compose.airflow.yml up -d --build
~~~

Consulte [docs/airflow-orchestration.md](../airflow-orchestration.md) para inicialização, acesso, execução e troubleshooting.

## Limitações conhecidas

- O ambiente Airflow é destinado a desenvolvimento e demonstração local, não a uma implantação produtiva de alta disponibilidade.
- O dataset acadêmico completo e as saídas intermediárias não são versionados no Git.
- O dashboard publicado utiliza agregações estáticas geradas pelo pipeline.
- Credenciais e segredos do ambiente local devem permanecer fora do versionamento.
